# v5.1 抽卡过渡实测

日期：2026-10-26。参考原站简体中文公开页面，桌面 1440×1000、手机 390×844，使用正常动态效果和真实浏览器时钟；原站仅允许 GET / HEAD / OPTIONS 请求。

## 原站可见行为

浏览器记录到抉择卡入场为 250ms、ease，透明度 0.6→1、纵向位移 8px→0；选项组为 700ms、ease-out，透明度 0.45→1。手机与桌面一致。选项出现初期按回车不会选中，显现完成后可以正常选择。新时间线条目有 400ms 的底色高亮，而不是把整段记录同时显示。

## 修改

- 按上述时长、位移、透明度和缓动实现抉择卡与选项显现。700ms 显现期防止误触；关闭与收起始终可以操作。
- 同一张卡切换自动模式时保留过渡进度，约三秒自动预览计时不变；显现完成后，手动接管立即生效。
- 每年与选择后的更新保留原有时间线和记录节点，新记录高亮；状态条平滑变化，场景在画面内容变化时短暂交叠过渡。年度进度条在暂停和切速时保持当前位置。
- 收起、重新展开及同年连续抉择会启动各自的入场；上一张卡延迟触发的关闭事件不会清掉下一张卡的状态。
- 尊重系统「减少动态效果」：立即显示内容，不额外锁定选项。

## 验证

`tests/browser_motion.py` 在 1440 / 390 两宽度、正常 / 减少动态两种设置实际走到十八岁及同年第二张卡。逐帧记录透明度、位置和选项状态，检查提前按回车不落选、旧记录节点保留、收起重开、自动切换后手动接管、同年卡片、手机折叠控件数量及无横向溢出。四组均通过，页面运行错误为空。

正常动画首帧记录卡片透明度 0.6、纵向位移 8px、选项透明度 0.45，结束时均为 1 且无位移。减少动态模式首帧即为最终状态。

另外完成六种屏宽布局、收藏与重载回归，两宽度约三秒自动预览与关闭冻结回归、零岁和少年结尾，以及四条完整浏览器人生。四局处理 81 张抉择卡，消费、冷却、冻结、重播和收藏通过。引擎及年内顺序 12 项测试通过。原有大规模规则压力测试见 v5.0 记录，本轮没有把旧测试数量冒充新动画验收。

本地证据位于 `output/birth-motion/`：原站 `reference-choice-motion.json`、`reference-mobile-motion.json` 及录屏；实现 `local/results.json` 为逐帧数据，`feel-final/`、`presentation/`、`bulk/` 为回归结果。公网结果部署后另记。该检查只验证这些过渡与操作，不代表全站已达到 1:1。
